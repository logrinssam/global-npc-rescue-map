# 지구촌 NPC 구조대 — 점검 결과와 활동지 구성안 (2026-10-13)

## 1. 점검 결과

### 지도 페이지 (https://logrinssam.github.io/global-npc-rescue-map/)
- 처음부터 끝까지 자동으로 돌려 봄: 조각 5개 수집 → 지도 완성 연출 → 비밀 임무(우리 모둠 NPC 카드) → 초기화. 자바스크립트 오류 0건, 콘솔 오류 0건, 깨진 이미지 0건.

### E-GPT 챗봇 5개
- 테아 챗봇으로 실제 대화 1회 테스트: "안녕! 나는 3모둠 바다야" → 별칭을 불러 주고, 장면을 2문장으로 들려준 뒤 질문 하나만 던짐. 공통 규칙(한 번에 질문 하나, 2-4문장)대로 동작.
- 다섯 챗봇 모두 학생 접속 공개, 메시지 전송 켜짐. 그리기·글쓰기·음성·갤러리·텍스트 복사는 꺼짐.
- **학습지(활동지)는 다섯 챗봇 모두 설정돼 있지 않음.** 1차 개발본에서 "관점 공감 기록지 또는 NPC 여권"이라고 적어 두었지만 파일도 만들어진 것이 없음. 지도 페이지의 "생각한 내용은 관점 공감 기록지에 적어요" 문구도 아직 실체가 없는 상태.

### E-GPT 학습지 기능이 무엇인지
- 챗봇 편집 → 학습지 탭에서 HTML 학습지를 붙일 수 있음. 학생 화면 옆에 학습지 패널이 뜨고, 학생이 칸을 채워 제출하면 교사가 넣은 루브릭으로 AI가 점수(기본 100점 만점)를 매김. "수정 제출 허용"을 켜면 평가받은 뒤 고쳐서 다시 낼 수 있음.
- 학습지는 "채팅으로 학습지+루브릭 만들기"(기본정보→성취기준→평가요소→사고수준→자료→발문→루브릭→검토 순으로 AI와 대화해 생성)나 HTML 직접 입력으로 만듦.
- 학생 기능 제어에 "학습지 입력 허용" 스위치가 있음(현재 꺼짐). 학습지를 붙이면 이 스위치를 켜야 학생이 적을 수 있음.

## 2. 활동지가 해야 할 일 (연구계획서 기준)
- 차시 3~7: NPC 1명당 "NPC 대화 활동지 / 관점 공감 기록지 / 선택 이유 기록 / 해결 주체 비교표"가 산출물.
- 검증 도구로 쓰임: 지구촌 문제 이해(대화 활동지·확인 문항), 관점 공감(관점 공감 기록지·성찰문), 해결 방안 탐색(제안서, 루브릭 5준거 4점 척도).
- 챗봇이 마지막에 내놓는 [학습 정리] 여섯 항목(문제 / 원인과 영향 / 인물의 감정과 필요 / 해결 주체 / 내가 제안한 해결 방안 / 한계)과 활동지 칸이 1:1로 맞아야 학생이 옮겨 적기 쉽고, 교사도 수합·분석이 쉬움.

## 3. 구성안

### 3-1. 전체 체제 (한 학생당 종이 3장 또는 소책자 1권 "NPC 여권")
| 구분 | 이름 | 쓰는 때 | 장수 |
|---|---|---|---|
| A | 관점 공감 기록지 (NPC 공통) | 테아·세이두·민·리마 각 1장 | 4 |
| B | 해결 주체 회의 기록지 (수현 전용) | 7차시 | 1 |
| C | 우리 모둠 NPC 기획안 | 완주 후, 8~9차시 | 1 |

"NPC 여권" 형태로 묶으면 표지에 세계 조각 스티커 5칸을 두어 지도 페이지의 조각 수집과 짝이 맞는다.

### 3-2. A. 관점 공감 기록지 (NPC 공통, 한 면)
챗봇 [학습 정리]와 같은 순서. 6학년이 10~12분 대화 뒤 5분 안에 채울 분량으로 칸을 크게.

1. **만난 사람** — 이름 / 사는 곳 / 얼굴 그림 붙이는 칸 (지도 페이지 얼굴과 같은 그림)
2. **이 사람이 겪는 지구촌 문제** — 한 문장
3. **왜 생겼고, 무엇이 달라지나** — "원인 → 생활의 변화" 화살표 칸 2~3개 (세이두 대화의 '날씨→농사→식량·돈→생활' 연결 그대로)
4. **이 사람의 마음과 가장 필요한 것** — 마음(낱말 3개 고르기: 걱정·속상함·희망·용기·답답함·…) + 가장 필요한 것 한 가지
5. **내가 고른 방법** — A/B/C 중 ○ 표시, 고른 까닭, 좋은 점 하나 / 어려운 점 하나
6. **함께할 사람** — 개인 / 마을·학교 / 정부 / 국제기구 / NGO / 다른 나라 체크 + 그 이유 한 줄
7. **공감 한 줄** — "내가 ○○라면, ______" (관점 공감 핵심 문항, 사전·사후 비교에 그대로 사용)
8. **세계 조각 칸** — 교사 도장 또는 스티커

### 3-3. B. 해결 주체 회의 기록지 (수현)
1. 가장 기억에 남는 인물과 까닭
2. 예산 10점 나누기 표 (긴급 식량·물 / 안전한 집·재난 대비 / 교육·어린이 보호 / 생계·기후 적응 / 주민 의견 듣기, 각 최대 4점·최소 1점 규칙 표기) — 처음 배분 / 돌발 상황 뒤 배분 두 줄
3. 가장 많이 준 영역과 까닭, 도움을 받기 어려워지는 사람
4. 주체별 할 일 표 (주민 / 정부 / 국제기구 / NGO / 시민 중 세 곳 이상)
5. 우리 모둠이 실천할 수 있는 일 한 가지

### 3-4. C. 우리 모둠 NPC 기획안
지도 페이지 카드(얼굴·이름·사는 곳·문제·첫인사·만든 모둠)와 같은 항목 + 연구계획서 9차시 항목(상황·감정·요구·미션·선택지 A/B/C·선택별 피드백). 지도 페이지의 카드 인쇄물을 붙이는 칸을 두면 디지털과 종이가 이어진다.

### 3-5. 루브릭 (연구계획서 5준거 4점 척도에 맞춤)
| 준거 | 4점 | 2점 |
|---|---|---|
| 문제 이해 | 문제를 인물의 생활과 연결해 구체적으로 씀 | 문제 이름만 씀 |
| 원인·영향 연결 | 원인→영향을 두 단계 이상 이어 씀 | 한 단계만 |
| 관점 공감 | 인물의 마음과 필요를 인물 입장에서 씀 | 자기 입장에서만 |
| 해결 주체 이해 | 주체와 역할을 알맞게 짝지음 | 주체만 고름 |
| 해결 방안 타당성 | 좋은 점과 어려운 점을 함께 씀 | 한쪽만 |

## 4. 운영 방식 비교와 추천
| 안 | 방식 | 장점 | 주의할 점 |
|---|---|---|---|
| ① 종이 기록지 (추천) | A·B·C를 인쇄해 "NPC 여권"으로 묶음 | 연구 산출물로 수집·분석이 쉬움, 모둠 활동과 맞음, 화면 두 개를 오갈 필요 없음 | 챗봇 [학습 정리]를 옮겨 적는 시간 5분 확보 |
| ② E-GPT 학습지 패널 | 챗봇마다 학습지+루브릭 붙이고 "학습지 입력 허용" 켬 | AI 자동 채점, 수정 제출, 교사 모니터링 화면에서 바로 확인 | 6학년이 대화창과 학습지를 동시에 쓰면 부담, 모둠 단위 기록이 어려움, 챗봇 5개에 각각 설정해야 함 |
| ③ 지도 페이지에 기록 기능 추가 | 임무 창에 기록 칸을 넣고 저장·인쇄 | 한 화면에서 끝남, NPC 카드처럼 인쇄 가능 | 서버가 없어 기기별 저장이라 수합은 인쇄·캡처로 해야 함 |

추천: **①을 기본**으로 하고, **②는 수현(5번) 챗봇에만** 붙여 "해결 주체 회의 기록지"를 AI 루브릭으로 채점하는 시범을 해 보는 것. 수현 대화는 예산 배분과 주체별 역할이라는 분명한 답 구조가 있어 자동 채점이 잘 맞고, 연구에서 'AI 활용' 근거 자료도 된다. 나머지 네 인물은 관점 공감이 핵심이라 종이에 손으로 쓰는 편이 분석에 유리하다.

## 5. 다음에 할 일
1. 위 구성안 확정 → A·B·C 인쇄용 파일 제작 (한글 또는 PDF, A4 한 면씩).

3. 지도 페이지 임무 창의 "관점 공감 기록지에 적어요" 문구에 기록지 번호(예: "기록지 ①에 적어요")를 넣어 종이와 연결.

## 7. 재검토 (2026-10-13, 수현 '돌발 상황' 확인)
- '돌발 상황'은 수현 챗봇 프롬프트 [대화 순서] 7번에 들어 있음: "새로운 재난이 생겨서 긴급 지원이 더 필요해졌어. 그런데 오래 가는 사업을 다 멈추면 내년에도 같은 문제가 생길 수 있어. 무엇을 바꿀까?" 1차 개발본, 입력용 문서, 새 계정에 저장된 실제 프롬프트, 10월 8일 테스트 기록("수정 후 돌발 상황 대응 통과") 모두 같음. 따라서 기록지 ⑤의 '처음 배분 / 돌발 상황 뒤' 두 줄은 챗봇 흐름과 맞음.

- E-GPT 학습지 문장 말투를 "~하시오"에서 "~해 보세요"로 바꿈(초등학생 수준 원칙).

A 정답(교사용, 검사지에는 인쇄되지 않음): 1① 2④ 3O 4② 5O 6① 7② 8O 9① 10X. B·C는 ①=1 … ⑤=5로 입력. D는 코딩표 수준(1~4, 무응답 0). 영역 구성: A 지식, B 관점 수용·공감(9), C 효능감·참여 의지(6: C1·C2·C5 효능감, C3·C4·C6 참여 의지).

### 9-2. 실시 시점
| 시점 | 대상 | 도구 | 비고 |
|---|---|---|---|
| 사후 (9차시 직후, 같은 날 또는 다음 날) | 학생 | 사후_회고검사지 | 20분. "수업 전의 나"를 떠올리는 안내를 교사가 먼저 읽어 주고 예시 문항을 함께 표시해 본다 |
| 지연 사후 (3~4주 뒤) | 학생 | 사후_회고검사지의 A·B·C("지금의 나" 칸만) + D② | 유지 효과 확인. 회고입력 시트를 복사해 "지연사후입력"으로 쓰면 같은 수식을 쓸 수 있다 |
| 수업 중 (3~6차시) | 학생 | 기록지 ①~④ 루브릭 채점 | 교사가 5준거 4점 척도로 채점해 루브릭추이 시트에 입력 |

### 9-3. 분석 순서
1. 회고입력·루브릭추이·챗봇로그 시트의 예시 3줄을 지우고 입력한다. D는 질적_코딩표.md로 두 사람이 코딩한 뒤 수준을 입력한다.
2. 회고결과: B·C의 수업 전 → 지금 변화(대응 t, d)와 D④ 성찰문 3·4수준 비율을 함께 본다.
3. 루브릭추이: 기록지 ①→④ 준거별 평균 추이와 그래프, 합계 ① vs ④ 대응 t.
4. 챗봇로그: E-GPT에서 별칭별 대화 내역을 내려받아 학생 질문을 F·E·S·O로 세어 입력하고, E+S 비율의 ①→④ 변화를 루브릭추이와 나란히 제시한다. E-GPT 학생 리포트는 코딩표 5-1절의 "중점" 문구로 뽑아 보조 자료로 쓴다.

### 9-4. 종이 응답을 크롬북으로 수합하기 (구글폼)
학생이 종이에 쓴 답을 크롬북에서 구글폼에 옮겨 적어 수합한다. 전사 오류를 줄이기 위한 절차:
1. **폼 만들기**: 크롬에서 script.google.com → 새 프로젝트 → `구글폼_만들기.gs` 내용을 붙여 넣고 `makeForm` 실행. 실행 로그에 폼 편집 주소·학생용 주소·응답 시트 주소가 나온다. 폼의 문항을 추가·삭제·이동하면 열 순서가 어긋나므로 문구만 고친다.
2. **학생 입력** (10분): 학생용 주소를 클래스룸이나 QR로 배포. 안내는 "종이에 쓴 것과 똑같이, 종이에 안 쓴 문항은 비워 두기". 모둠은 드롭다운(1~5모둠), 별칭은 학생이 직접 쓴다(모둠 번호 빼고 별칭만). 변환 시트가 앞뒤 공백을 지우고 "1모둠 바다" 꼴로 합치므로, 챗봇·종이와 다른 글자로 쓴 별칭만 교사가 응답 시트에서 고친다. B·C 그리드는 필수가 아니다(빈칸을 억지로 고르지 않게).
3. **검수**: 종이를 걷은 뒤 5명(20%)의 종이와 폼 응답을 대조해 불일치 칸 수를 적는다(연구 한계·신뢰도 보고용). 응답 시트에서 같은 별칭이 둘이면 마지막 것만 남긴다(폼붙여넣기 시트가 "중복!"으로 표시).
4. **변환**: 구글 응답 시트 전체 선택 → 복사 → `사후_분석.xlsx` 폼붙여넣기(회고) 시트 A4에 붙여넣기. 오른쪽 노란 블록(별칭 ~ D 수준)이 자동으로 채워지면 복사해 회고입력 시트 4행에 "값만 붙여넣기". D 원문은 블록 오른쪽에 함께 나오므로 코딩할 때 보고 D 수준 칸에 적는다.
5. **대안**: 교사가 직접 입력(25명 × 약 45칸, 40분)하면 전사 오류가 가장 적다. 학생 입력을 하면 1~4의 검수를 꼭 한다.

### 9-5. 연구 한계 문구 예시
> 본 연구는 수업 전에 사전검사를 실시하지 못하였다. 이에 사전검사를 회고적 사전·사후 설계(retrospective pre-post, then-test; Howard, 1980)로 대체하여 사후 시점에 "수업 전의 나"와 "지금의 나"를 같은 문항으로 응답하게 하였다. 회고적 응답은 학생의 기억과 변화 기대에 영향을 받을 수 있으므로, 수업 중 작성한 기록지 ①~④의 루브릭 점수 추이와 챗봇 대화 기록, 성찰문의 질적 분석을 함께 제시하여 결과를 해석하였다. 또한 비교 집단을 두지 않은 단일 집단 설계이므로 변화를 수업 효과로만 해석하는 데 한계가 있다.

참고: Howard, G. S. (1980). Response-shift bias: A problem in evaluating interventions with pre/post self-reports. *Evaluation Review, 4*(1), 93–106.
